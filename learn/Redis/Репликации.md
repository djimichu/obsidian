## Асинхронная репликации и Масштабируемость

Обязательно необходимо делать репликации Redis кэша. Это называется *кластером*. 

Также можем масштабировать наш Redis чтобы распределить нагрузку на оперативную память. У нас получаются как партиции в БД. Их мы также реплицируем для безопасности наших данных.

У нас есть master узел, куда ведутся записи, а также есть зависимые от него реплики. 
Записи **только в master**, чтение с реплики или master. Это помогает уменьшить нагрузку на чтение.

Если master падает, то какая-либо реплика становится новым мастером(та, что меньше всего отстаёт).

# Redis кластер.

Когда нам не хватает памяти в master нам поможет только увеличение числа мастеров.

Мы добавляем мастеров, которые хранят разные данные и у них свои реплики.
- Данные делятся по 16384 hash слотам
- Каждый **мастер** хранит часть слотов 
- У каждого мастера могут быть реплики для отказоустойчивости

> [!example]- Наглядно:
> ```
> Master-1 (slots 0-5000) -> Replica-1a, Replica-1b
> Master-2 (slots 5001-10000) -> Replica-2a
> Master-3 (slots 10001-16383) -> Replica-3a, Replica-3b
> ```
> Если добавляем мастеров, то hash слоты перераспределяются
