# Паттерны кеширования

## 1. Cache-aside (самый популярный)

### Суть

сначала проверяем кеш → если нет → идём в БД → кладём в кеш

---

> [!success]- Алгоритм
> 1. GET из кеша  
> 2. если есть → вернуть  
> 3. если нет → запрос в БД  
> 4. записать в кеш  
> 5. вернуть результат

---

> [!example]- Пример на Go (Redis)
> ```go
> val, err := rdb.Get(ctx, "product:1").Bytes()  
>   
> if err == redis.Nil {  
>     // нет в кеше → идём в БД  
>     product := db.GetProduct(1)  
>   
>     data, _ := json.Marshal(product)  
>   
>     rdb.Set(ctx, "product:1", data, time.Minute)  
>   
>     return product  
> }  
> 
>   
> var product Product  
> json.Unmarshal(val, &product)  
> return product
> ```

---

### Плюсы

- простой
    
- гибкий
    
- полный контроль в коде
    

### Минусы

- возможен **cache miss latency**
    
- риск устаревших данных

## 2. Write-through

#### Суть:

==запись идёт сразу в кеш и в БД==

---
#### Алгоритм

1. write → cache  
2. write → DB

---
#### Плюсы

- кеш всегда актуальный
    

#### Минусы

- медленнее запись
    
- сложнее поддержка

## 3. Write-back (write-behind)

### Суть

==пишем в кеш → БД обновляется позже (асинхронно)==

---
#### Плюсы

- очень быстрые записи
    

#### Минусы

- риск потери данных
    
- сложная реализация

## 4. Read-through

### Суть

==кеш сам ходит в БД==

Но:

в Go почти не используется

потому что:

- Redis — тупой storage, не знает про БД
    
- логика обычно в приложении
