## IN-MEMORY БД. REDIS

Когда в нашем приложении появляются высокие нагрузки, которые мы не можем быстро обрабатывать используя обычную нашу БД, мы можем воспользоваться нереляционной БД, мы будем посылать уникальные запросы как и раньше в основную БД, а для повторяющихся запросов мы как раз будем использовать NoSQL БД

Redis хранит все данные на оперативной памяти. За счёт этого она очень быстрая

Она хранит данные типа *ключ-значение*  

Чтение примерно в 10.000 раз быстрее чем в обычной БД.

У нас есть популярные данные, нам нужна скорость, берем Redis

## Структуры данных в Redis

Мы можем хранить разные данные, вот примеры:

> [!tip]- Строки 
> ```
> @mr_scott  ---  "Босс"
> ```
> 
> > Обычная строка, доступная по ключу
> > Типичный словарь

> [!tip]- Списки 
> ```
> @mr_scott  ---	"Босс",
> 				"Комик",
> 				"Босс"
> ```
> 
> > Связный список

> [!tip]- Хэши
> ```
> @mr_scott 
>   ---
> {
>  name: Майкл Скотт,
>  bio: Босс Дандер Мифлин,
>  birthday: 14.06.1966
> }
> ```
> > Формат 
> > поле: данные

> [!tip]- Множества 
> ```
> @mr_scott  ---	"Босс",
> 				"Комик",
> 				"Плейбой"
> ```
> 
> > Нет дубликатов

> [!tip]- Сортированные множества
> ```
> @mr_scott  ---	"Плейбой": 1,
> 				"Комик": 2,
> 				"Босс": 3
> ```
> 
> > Авто сортировка по счету

> [!tip]- Гео-индексы
> ```
> earth
>  ---
> 13.569318
> 38.571592
> "Палермо"
> ```
> > Можно искать в радиусе


## Однопоточность и Неконсистентность

Redis у нас однопоточен, и когда у нас есть кластер, допустим на одном мы сохранили данные, а на втором еще не успели и делаем запрос на этот сервер, мы можем не получить наши данные, которые мы вроде как записали. Это называется **НЕКОНСИНСТЕНТНОСТЬ**.
