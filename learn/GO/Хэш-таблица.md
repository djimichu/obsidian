# Хеш-таблицы.

Итак, у нас есть хеш-мапы, это ключ значение где ключом может быть любой тип данных который можно сравнить( !=, == ), как и значение, тоже любой тип.
Ключи всегда уникальны, если передать уже имеющийся ключ то значение будет просто перезаписано на новое.

Хеш-мапа с помощью хеш-функций превращает ключ(например строка) в число и обращается к числу будто это массив.

Хеш-таблица это массив, в котором есть определенное число bucket's(ячеек) в которых хранятся наши пары ключ-значений. В бакете может быть максимум 8 пар, потом он создает overflow1 и туда кладет новые пары. Каждый бакет имеет _один указатель_ на overflow-бакет, то есть на своё продолжение(если есть)

-

Бакет — это **структура из фиксированного размера**, содержащая:

```
tophash[8]   // первые 8 бит хеша для быстрого фильтра
keys[8]      // массив ключей
values[8]    // массив значений
overflow *bucket   // ссылка ТОЛЬКО на overflow, если есть
```

`tophash` — это **массив из 8 байт**, один байт на каждый слот внутри бакета.

Каждый байт = **старшие 8 бит хеш-функции** ключа, который лежит в соответствующем слоте.

То есть:
```
tophash[0] → первые 8 бит хеша key[0]
tophash[1] → первые 8 бит хеша key[1]
...
tophash[7] → первые 8 бит хеша key[7]
```


> [!example]- tophash объяснение
> ## 🔹 Шаг 1: считаем хеши ключей (64 бит)
Допустим Go дал:
>
>
| key    | hash (64 бит, hex)      |
| ------ | ----------------------- |
| КЛЮЧ01 | `0xA3F0_11BC_98D4_0021` |
| КЛЮЧ02 | `0x3F22_991C_A0B1_0103` |
>
>## 🔹 Шаг 2: Берём старший байт хеша (top 8 bits)
Это просто **первые два hex-символа**.
>
>
| key    | hash (hex)            | tophash raw |
| ------ | --------------------- | ----------- |
| КЛЮЧ01 | `A3F0 11BC 98D4 0021` | `A3`        |
| КЛЮЧ02 | `3F22 991C A0B1 0103` | `3F`        |
>
>```
если tophash[i] != 3F → пропустить элемент
если tophash[i] == 3F → сравнить ключи
если key[i] == "КЛЮЧ02" → нашли
>```
>
>Это фильтр, чтобы:
>- **не сравнивать строки**
   > 
>- быстрее пропускать элементы, которые точно не подходят
>
>Зарезервированные значения:
>- 0 — пусто
   > 
>- 1, 2, 3 — служебные марки эвакуации при grow

> [!example]- hmap
> ## **hmap — верхнеуровневая структура**
Содержит:
>- `count` — число элементов
   > 
>- `B` — log₂(bucketCount)
   > 
>- `buckets` — массив bucket'ов
   > 
>- `oldbuckets` — массив старых bucket’ов при grow
   > 
>- `nevacuated` — сколько бакетов уже перенесено
   > 
>- `hash0` — random seed для хеша

> [!example]- bmap
> # **bucket (bmap) — базовый элемент хранения**
> 
> Каждый bucket содержит:
> 
> - `tophash[8]` — старшие 8 бит хеша ключей
>     
> - `keys[8]` — ключи
>     
> - `values[8]` — значения
>     
> - `overflow` — указатель на следующий overflow-бакет
>     
> 


# Коллизия.

Go использует **комбинированную схему**, которая не совпадает ни с “чистыми” цепочками, ни с открытой адресацией.  
На собеседовании правильный ответ звучит так:

✔ Go использует **hybrid hashing**:

**закрытая адресация в пределах бакета (slotted array) + внешние цепочки через overflow-бакеты.**
То есть **внутри бакета коллизии решаются через перебор слотов**.
А сами бакеты образуют цепочки.


В открытой адресации один bucket = один slot = одна пара ключ-значение. Коллизия решается поиском свободных ячеек(пробирование), исключая указатели.
В нашей же один bucket = 8 slots
