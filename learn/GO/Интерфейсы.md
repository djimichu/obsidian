# Интерфейсы

## **Интерфейсы в двух словах**

**Интерфейс в Go** — это контракт, который описывает набор методов.

Если структура содержит **все указанные методы**, она **автоматически** считается реализацией интерфейса — **без явного указания**.

Это работает благодаря принципу **утиной типизации**, суть которого очень проста:

> "Если что-то выглядит как утка, плавает как утка и крякает как утка — скорее всего, это утка."

В Go это означает следующее:

- Не нужно явно указывать, что структура реализует интерфейс.
- Если структура содержит все необходимые методы, Go сам это определит.

> Например, если структура содержит метод Work(), а интерфейс требует только метод Work(), этого уже достаточно.

## Как работают интерфейсы на самом деле

Внутри Go интерфейс — это особая структура. Она содержит **информацию о типе** и **указатель на реальные данные**. Это можно увидеть в исходниках Go:

```go
// <https://golang.org/src/runtime/runtime2.go>  
  
type iface struct {  
    tab  *itab  
    data unsafe.Pointer  
}
```

- **tab** — Указатель на тип объекта.
- **data** — Указатель на реальные данные (ваш объект).

**Рассмотрим следующий пример:**

```go
type Man struct{}  
  
func (m Man) Sleep() {}  
func (m Man) Eat()   {}  
func (m Man) Work()  {}  
  
type Programmer interface {  
    Work()  
}  
  
func main() {  
    var man *Man
    fmt.Printf("%#v\\n", man)           // (*main.Man)(nil)
    
    var worker Programmer
    fmt.Printf("%#v\\n", worker)        // <nil>
    
    worker = man
    fmt.Printf("%#v\\n", worker)        // (*main.Man)(nil)
    
    fmt.Printf("%t\\n", man == nil)     // true
    fmt.Printf("%t\\n", worker == man)  // true
    fmt.Printf("%t\\n", worker == nil)  // false
}
```

Здесь возникает важный момент: несмотря на то, что переменная `man` равна `nil`, переменная `worker` после присваивания уже не `nil`. Почему?

Потому что в Go интерфейс считается равным `nil` **только если**:

- и `tab` (информация о типе),
    
- и `data` (указатель на данные)
    
    оба одновременно равны `nil`.
    

В данном случае `tab` уже содержит информацию о типе `*Man`, даже несмотря на то, что сам объект `man` равен `nil`. Поэтому `worker != nil`.

## Что такое nil-интерфейс?

**Nil-интерфейс** — это интерфейсная переменная, в которой **нет ни типа, ни значения**. Это особый случай, и именно он сравнивается с `nil` как `true`.

```go
var p fmt.Stringer
fmt.Println(p == nil) // true — потому что это nil-интерфейс
```

Внутри такого интерфейса:

- `tab == nil` — нет информации о типе,
- `data == nil` — нет значения.

Если в интерфейс положить `nil`-указатель на конкретный тип, то тип уже появится — и интерфейс перестанет быть `nil`.

```go
var s *string = nil
var val any = s
fmt.Println(val == nil) // false — интерфейс уже содержит тип "*string"
```

Это поведение часто становится причиной неожиданного `val != nil`, даже если значение выглядит как `nil`.

## Вопросы с собеседований

- **Что такое интерфейс в Go?**
	- Интерфейс в Go — это **контракт**, который определяет набор методов. Любой тип, реализующий все методы интерфейса, **неявно** считается его реализацией.
- **Как работает реализация интерфейса в Go? Нужно ли что-то явно указывать?**
	- Не нужно. Go использует **утиную типизацию** — если тип содержит все методы, описанные в интерфейсе, он считается его реализацией. Никаких деклараций или ключевых слов не требуется.
    
- **Что такое пустой интерфейс (`interface{}`)?**
    - Это **интерфейс без методов**. В него можно положить **значение любого типа** — строку, число, структуру и т.д.
    
    - Пример:
    
	    ```go
	    var x interface{}
	    x = 42
	    x = "hello"
	    x = []int{1, 2, 3}
	    ```
    
	    Но чтобы снова работать с этим значением — нужно узнать, что внутри, и привести к нужному типу:
    
	    ```go
	    s, ok := x.(string)
	    ```
	    
	    Пустой интерфейс часто используется, когда заранее **неизвестно**, с каким типом вы будете работать (например, в JSON, логах или универсальных функциях).
	    
- **Из чего состоит интерфейс под капотом?**
    
    - Интерфейс — это структура из двух полей:
    
    - `tab` — указатель на тип,
    - `data` — указатель на значение.
- **Что такое nil-интерфейс?**
    
    - Nil-интерфейс — это интерфейс, в котором оба поля равны nil (tab == nil, data == nil). Только в этом случае при сравнении интерфейса и `nil` вернет `true`.
    
- **Что произойдёт, если вызвать метод интерфейса, содержащего nil?**
    
    - Будет паника:
    
	    ```go
	    panic: runtime error: invalid memory address or nil pointer dereference
	    ```
	    
	    Метод вызовется на `nil`, и это приведёт к ошибке доступа.
	    
- **Как проверить, что интерфейс содержит значение конкретного типа?**
    
    - Через **type assertion**:
    
	    ```go
	    val, ok := iface.(T)
	    ```
    
	    Или через **type switch**:
    
	    ```go
	    switch v := iface.(type) {
	    case string:
	        ...
	    }
	    ```
    
- **Может ли структура реализовать несколько интерфейсов?**
    
    - Да. В Go нет ограничений — если структура реализует методы нескольких интерфейсов, она совместима с каждым из них.
