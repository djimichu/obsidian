# 📌 1. Стек vs Куча (Stack vs Heap)

Это база для понимания работы Go рантайма.

### **Стек**

- область памяти, привязанная к конкретной горутине
    
- хранит **локальные переменные**, параметры функций
    
- очень быстрый (LIFO)
    
- автоматически освобождается при выходе из функции
    
- не требует работы GC

Размер стека в Go: динамический, начинается с ~2 KB и растёт по мере необходимости.

---

### **Куча**

- общая область памяти процесса
    
- на куче хранятся данные, которые **живут дольше вызова функции**
    
- выделение дороже
    
- требуется работа GC для освобождения
    
- может приводить к дополнительной нагрузке на рантайм




# 📌 2. Escape Analysis (анализ выхода за рамки стека)

Это механизм, который решает:  
**разместить объект на стеке или в куче**.

Если переменная «уходит» за пределы функции → в кучу.

Пример:

```go
func makeSlice() *int {
    x := 10
    return &x  // x попадает в кучу
}
```

Если Go может гарантировать, что объект живёт только внутри функции → стек:

```go
func sum(a, b int) int {
    x := a + b // на стеке
    return x
}
```

Когда происходит escape:

- возврат указателя на локальную переменную
    
- захват переменной замыканием
    
- слишком большой объект, который не помещается в stack frame
    
- интерфейсы, когда Go не может определить точный тип

# 📌 3. Garbage Collector (GC)

Go использует **триадный, инкрементальный, concurrent, mark-and-sweep GC**.

Простыми словами:

### Фаза 1. **Mark**

GC отмечает объекты, до которых можно «дойти» из корней (goroutine stacks, global variables).

### Фаза 2. **Sweep**

Очищает всё, что не помечено.

### Особенности Go GC:

- **parallel** — несколько потоков делают mark/sweep
    
- **concurrent** — работает параллельно с твоим кодом
    
- **stop-the-world минимален** (<1 ms обычно)
    
- Pauses минимальны
    
- Частично трассирует pointer graph инкрементально
