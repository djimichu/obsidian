 # Введение.


Что если часть данных обновилась, а часть нет?
- Транзакция - логическая группа операций
- Транзакция может быть выполнена только целиком(всё или ничего)
- Классический пример: банковская транзакция
	- прочесть баланс на счету X
	- уменьшить баланс на Z денежных единиц
	- сохранить новый баланс счёта Х
	- прочесть баланс на счету Y
	- увеличить баланс на Z денежных единиц
	- сохранить новый баланс счёта Y

К транзакциям есть набор требований, **ACID** описывает требования к концепционной системе:
- Atomicity(атомарность)
	- Гарантирует, что никакая транзакция не будет зафиксирована в системе частично, либо все подоперации, либо ни одной
	- Если транзакцию не удается полностью завершить, результаты всех её до сих пор произведенных действий будут отменены (ROLLBACK), система вернется в исходное состояние
- Consistency(консистентность, согласованность)
	- Гарантирует, что система не сможет провести неразрешенные операции, нарушить ограничения, CONSTRAINT, триггеры и все различные правила(именно со стороны СУБД, а не бизнес-модели)
- Isolation(изолированность)
	-  Данные обрабатываемые одной транзакцией изолируются от других транзакций на время требуемое исходной транзакцией для выполнения всех своих действий 
	- Зачем? - 
	- В рамках проведения транзакций, данные не могут быть согласованны в каждый малый момент времени
> [!tip]- Пример
> Мы списали деньги с одного счёта, и до тех пор, пока не зачислили ту же сумму на другой счёт, данные не согласованны. Хоть и этот промежуток очень мал, но в него могут и будут вклиниваться другие транзакции, которые будут видеть эту несогласованность в моменте. Именно для этого нужна изолированность транзакций

- Durability(долговечность)
	- Гарантирует, что если транзакция успешно выполнилась, то уже никакие сбои не вызовут отката действий.



## TCL - Transaction Control Language

- START TRANSACTION / BEGIN \[TRANSACTION] - (необязательно)
- END  \[TRANSACTION] / COMMIT
- BEGIN / COMMIT - SQL standard
- START TRANSACTION / END  \[TRANSACTION] - pgSQL extension
- Пример:
	BEGIN;
	statement1;
	statement2;
	statement3;
	COMMIT;
- **Все операции обёрнуты в транзакции в любом случае**(всё и всегда)
- Если по ходу транзакции что-то пошло не так, её можно откатить: **ROLLBACK**
- Внутри транзакции можно делать "засечки" в "важных" местах с помощью команды `SAVEPOINT` *savepoint_name*
- Откат к точке **ROLLBACK TO** *savepoint_name*

Важные моменты:

- Нельзя явно создавать транзакции в функциях
- Хотя функции неявно исполняются в рамках транзакции
- Чтобы прервать транзакцию изнутри функции - RAISE EXCEPTION
- Если хотим откатить только часть - можно "имитировать" savepoint с помощью BEGIN и EXCEPTION WHEN
- Концепция подразумевает, что уровнем изоляции и откатами управляет внешний код (SQL-скрипт или код приложения верхнего уровня(Golang))
