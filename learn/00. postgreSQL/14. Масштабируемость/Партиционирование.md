# Партиционирование.

**Простыми словами:** Большую таблицу **физически разбиваем на несколько кусков (партиций)** по какому-то правилу, но все эти куски лежат **в рамках одного сервера БД**.

**На примере:**  
Таблица `orders` (заказы) с миллиардом записей. Делим её по дате:

- `orders_2023`
    
- `orders_2024`
    
- `orders_2025`
    

Когда ты делаешь запрос `SELECT * FROM orders WHERE date = '2024-12-01'`, Postgres **смотрит только в партицию `orders_2024`**, а не во всю огромную таблицу. Это **ускоряет** запросы.

**Зачем?**

- **Производительность:** Ускорение запросов (особенно с `WHERE` по ключу партиции).
    
- **Управление данными:** Легко удалить старые данные (`DROP TABLE orders_2020`), архивировать.
    

**Минусы:** Всё ещё один сервер. Если он упрётся в потолок по CPU/диску — это потолок для всей системы.

**Как объяснить на собесе:** "Это горизонтальное разделение таблицы на более мелкие части (партиции) внутри одного инстанса БД для ускорения запросов и удобства управления данными (например, по диапазону дат)."
