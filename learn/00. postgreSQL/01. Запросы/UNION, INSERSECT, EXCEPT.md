### UNION - Объединение
### INTERSECT - Пересечения
### EXCEPT - Исключения

1. Мы можем объединять результаты запросов с разных таблиц. Например нам необходимо получить список всех стран откуда наши заказчики и работники. С помощью ключевого слово #UNION мы получим список стран обеих таблиц **без дубликатов**

	```sql
	SELECT страна
	FROM сотрудники
	UNION
	SELECT страна
	FROM заказчики
	```
>[!example]-
>Список сотрудников:
>
| имя     | номер | страна   |
| ------- | ----- | -------- |
| Василий | 89352 | Россия   |
| Вадим   | 89872 | Беларусь |
| Адам    | 89275 | Россия   |
| Петр    | 89125 | Китай    |
| Алексей | 89356 | Беларусь |
| Дмитрий | 89156 | Италия   |
Список заказчиков:
>
>| имя      | номер | страна   |
| -------- | ----- | -------- |
| Андрей   | 89347 | Китай    |
| Илья     | 89943 | Испания  |
| Анатолий | 89236 | Россия   |
| Даниил   | 89658 | США      |
| Тимур    | 89271 | Германия |
| Владимир | 89398 | Беларусь |
>**Результат**:
>
| страна   |
| -------- |
| Россия   |
| Беларусь |
| Китай    |
| Италия   |
| Испания |
| США  |
| Германия      |
Как видим, тут нет дубликатов, однако, если они нам нужны, то мы пишем UNION ALL и получаем таблицу с дубликатами!

2. Если с UNION всё понятно, он просто объединяет записи из разных таблиц, то #INTERSECT не объединяет, а ищет те данные, которые есть в обеих таблицах, т.е. ищет пересечения. Для примера возьмём те же данные.
	```sql
	SELECT страна
	FROM сотрудники
	INTERSECT
	SELECT страна
	FROM заказчики
	```
>[!example]-
>Список сотрудников:
>
| имя     | номер | страна   |
| ------- | ----- | -------- |
| Василий | 89352 | Россия   |
| Вадим   | 89872 | Беларусь |
| Адам    | 89275 | Россия   |
| Петр    | 89125 | Китай    |
| Алексей | 89356 | Беларусь |
| Дмитрий | 89156 | Италия   |
Список заказчиков:
>
>| имя      | номер | страна   |
| -------- | ----- | -------- |
| Андрей   | 89347 | Китай    |
| Илья     | 89943 | Испания  |
| Анатолий | 89236 | Россия   |
| Даниил   | 89658 | США      |
| Тимур    | 89271 | Германия |
| Владимир | 89398 | Беларусь |
>**Результат**:
>
| страна   |
| -------- |
| Россия   |
| Беларусь |
| Китай    |
Тут мы видим, что в обеих таблицах есть только 3 общие страны, Россия, Беларусь и Китай, только они и входят в результирующий набор с INTERSECT

 2. Следовательно, можно догадаться, если UNION объединяет, INTERSECT ищет пересечения, то #EXCEPT ищет исключения, которые есть только в первой таблице, а во второй нет. На примере всё сразу станет понятно.
	```sql
	SELECT страна
	FROM сотрудники
	EXCEPT
	SELECT страна
	FROM заказчики
	```
>[!example]-
>Список сотрудников:
>
| имя     | номер | страна   |
| ------- | ----- | -------- |
| Василий | 89352 | Россия   |
| Вадим   | 89872 | Беларусь |
| Адам    | 89275 | Россия   |
| Петр    | 89125 | Китай    |
| Алексей | 89356 | Беларусь |
| Дмитрий | 89156 | Италия   |
Список заказчиков:
>
>| имя      | номер | страна   |
| -------- | ----- | -------- |
| Андрей   | 89347 | Китай    |
| Илья     | 89943 | Испания  |
| Анатолий | 89236 | Россия   |
| Даниил   | 89658 | США      |
| Тимур    | 89271 | Германия |
| Владимир | 89398 | США |
>**Результат**:
>
| страна   |
| -------- |
| Беларусь   |
| Италия |
Только те страны, которых нет во второй таблице (Беларусь, Италия - есть только в первой таблице) БЕЗ ДУБЛИКАТОВ! EXCEPT ALL работает как UNION ALL, т.е. позволяет получать дубликаты этих стран (было бы дважды Беларусь)
