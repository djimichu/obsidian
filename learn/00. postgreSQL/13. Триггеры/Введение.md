# Введение.

## Событийное программирование в Postgres

Иногда нам необходимо программно реагировать на изменение данных, события. Но как это сделать в Postgres?

Триггер - объект, который назначает действие на те или иные события(реакция)

- Триггеры могут реагировать как на построчное изменение(множественные срабатывания), так и единожды на все изменения сразу 
- Сценарии использования триггеров:
	- Аудит таблиц
	- Дополнительные действия в ответ на изменения
	- Сложные проверки целостности
- Что необходимо:
	- Для совершения действия необходима функция
	- И сам объект триггера

--- 
#### **Создание *построчного* триггера:**
```sql
CREATE TRIGGER trigger_name() condition ON table_name -- условие вызова ответа
FOR EACH ROW EXECUTE FUNCTION function_name(); -- ответная функция
```

>**Построчный триггер (FOR EACH ROW)** сработает **для каждой измененной строки отдельно**. Если обновлено 100 записей, тело триггера выполнится 100 раз.

**Condition:**
\[BEFORE, AFTER] \[INSERT, UPDATE, DELETE]

**Например:**
```sql
BEFORE INSERT -- до вставки
AFTER UPDATE -- после апдейта
BEFORE INSERT OR UPDATE -- до вставки или апдейта
```

#### **Удаление:** 
```sql
DROP TRIGGER IF EXISTS trigger_name ON table_name
```

#### **Переименование триггера:**

```sql
ALTER TRIGGER trigger_name ON table_name
RENAME TO new_trigger_name;
```

#### **Отключение триггера/всех триггеров таблицы**
```sql
ALTER TABLE table_name
DISABLE TRIGGER trigger_name;

------
ALTER TABLE table_name
DISABLE TRIGGER ALL;
```
