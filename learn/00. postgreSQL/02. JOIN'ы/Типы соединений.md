### Типы соединений между несколькими таблицами

1. **INNER JOIN** - внутреннее соединение, можем писать просто JOIN
2. **LEFT Outer JOIN, RIGHT Outer JOIN** - левое и правое внешнее соединение
3. **FULL JOIN** - полное соединение
4. **CROSS JOIN** - декартово произведение
5. **SELF JOIN** - соединение на саму себя

>[!tip]- Подсказка
>Простая аналогия:
>- **`INNER JOIN`** — только общие данные
>- 
>- **`RIGHT JOIN`** — правая таблица "главная", ее данные не теряются
>- 
>- **`LEFT JOIN`** — левая таблица "главная", ее данные не теряются
>- 
>- **`FULL JOIN`** — все данные из обеих таблиц

#### INNER JOIN

1. ```sql
   SELECT id, Исполнитель, Страна, Песня, Год_выпуска
   FROM tracks
   INNER JOIN artists ON tracks.artists_id = artists.id
   ```

   Получаем Результат\_1, можем сортировать по году ORDER BY Год\_выпуска DESC

> Также, если у нас, допустим, в обеих таблицах столбцы называются одинаково, чтобы избежать ошибок и проблем можем назвать в SELECT таблица.столбец - tracks.Песня, tracks.Год_выпуска
> 
> Желательно называть столбцы с id одинаково, то есть мы назвали просто id, но лучше писать artists_id, также как и во вторичных ключах ссылающихся на них таблиц
> Также можно писать множественные соединения (больше двух):

```sql
SELECT исполнитель, альбом, число_треков, песня, год_выпуска
FROM tracks
JOIN alboms ON tracks.artists_id = alboms.artists_id
JOIN artists ON alboms.artists_id = artists.id
```

Следует понимать, что тут все мои запросы, а также таблицы, максимально упрощены и написаны исключительно для понимания действия, я написал условно, если бы у нас была таблица альбомов, но так как тут довольно неудобно всё это делать, проще будет понять на нормальной таблице northwind

#### LEFT JOIN

1. ```sql
   SELECT id, Исполнитель, Страна, Песня, Год_выпуска
   FROM artists
   LEFT JOIN tracks ON tracks.artists_id = artists.id
   ```
Вот тут теперь мы видим, какая таблица у нас справа, а какая слева. Слева tracks, идёт после FROM, справа artists, идет после JOIN. Получаем все строки из левой таблицы tracks(Результат_2).

#### CROSS JOIN

При CROSS JOIN запрос точно такой же как и INNER или LEFT, только отсекается часть с ON, так как она просто-напросто не нужна.
1. ```sql
   SELECT id, Исполнитель, Страна, Песня, Год_выпуска
   FROM artists
   CROSS JOIN tracks 
   ```
Ну результат соответственно Результат_4

#### SELF JOIN

Этот тип соединения по факту работает с одной таблицей, иерархически завязанной между собой, то есть у нас есть допустим таблица, в которой описаны все работники, у каждого из них есть столбец, который указывает на менеджера этого работника из этой же таблицы. То есть у нас одна таблица, работники, но кто-то из них например главный, у него не будет id менеджера, ссылаться могут только на него и его подчиненных, проще всего будет понять на примере


> [!example]- Пример
> 
| работник_id  | имя     | фамилия | менеджер_id |
| --- | ------- | ------- | ------------ |
| 1   | Сергей  | Иванов  | NULL         |
| 2   | Анна    | Петрова | 1            |
| 3   | Дмитрий | Смирнов | 1            |
| 4   | Мария   | Козлова | 2            |
| 5   | Павел   | Соколов | 2            |
| 6   | Алексей | Волков  | 2            |
| 7   | Дамир   | Джудах  | 3            |
| 8   | Олег    | Бочаров | 3            |
В нашей таблице Сергей Иванов является главным, у него нет привязки к кому-то, а 2 и 3 работник являются менеджерами, они зависят от главного, а от них зависят другие работники, которые ниже по рангу. Притом у 2го менеджера три подчиненных, а у 3го менеджера только два подчиненных

1. ```sql
   SELECT e.имя || ' ' || e.фамилия AS employee
		   m.имя || ' ' || m.фамилия AS manager
   FROM работники e
   LEFT JOIN работники m ON m.работник_id = e.менеджер_id
   ORDER BY manager
   ```

## Пример сокращения кода

Вот так один из запросов выглядит без сокращений:
```sql
SELECT shippers.company_name, employees.first_name || ' ' || employees.last_name
FROM orders
JOIN customers ON orders.customer_id = customers.customer_id
JOIN employees ON orders.employee_id = employees.employee_id
JOIN shippers ON ship_via = shipper_id
WHERE employees.city = 'London' AND customers.city = 'London' AND shippers.company_name = 'Speedy Express'

```

А вот версия с сокращением и упрощением:
```sql
SELECT s.company_name, CONCAT(e.first_name, ' ', e.last_name)
FROM orders
JOIN customers AS c USING(customer_id)
JOIN employees AS e USING(employee_id)
JOIN shippers AS s ON ship_via = shipper_id
WHERE e.city = 'London'
   AND c.city = 'London'
   AND s.company_name = 'Speedy Express'
```

Выглядит гораздо лучше и серьезнее, нежели первый вариант. При соединении таблиц мы назначаем ей имя с помощью AS и первой буквы таблицы, так мы сможем не писать каждый раз полностью имя таблицы.
