## Ограничения.

Помимо NOT NULL, UNIQUE, PRIMARY KEY и FOREIGN KEY есть также и некоторые другие виды ограничений для колонок.

1. CHECK (CHK) - мы можем явно прописывать условия для данных нашей колонки

> [!example]-
> ```sql
> ALTER TABLE book
> ADD COLUMN price decimal CONSTRAINT chk_book_price CHECK (price >= 10)
> ```

> В данном случае мы явно прописали, что в колонке price таблицы book, цена не может быть ниже 10. Если ввести запрос с вставкой цены менее 10, то будет ошибка ограничений.
> 
> SQL state: 23514. ERROR: новая строка нарушает ограничение-проверку "chk_book_price"


2. DEFAULT - еще одно ограничение, хоть и не в прямом смысле этого слова. Иногда мы хотим, чтобы в какую-то колонку обязательно что-то записывалось, и мы можем использовать это ограничение, чтобы даже если в эту колонку при записи ничего не записали, автоматически будет назначено значение.

> [!example]- Создаем таблицу с DEFAULT колонкой
> ```sql
> CREATE TABLE customer
> (
> 	customer_id serial,
> 	full_name text,
> 	status char DEFAULT 'r',
> 	
> 	CONSTRAINT pk_customer PRIMARY KEY(customer_id)
> 	CONSTRAINT chk_customer_status CHECK (status = 'r' OR status = 'p') 
> )
> ```

> Теперь если мы вставляем туда данные без указания поля status, то по умолчанию будет вставлено значение 'r' - от regular


> [!example]- Можем также убирать ограничение DEFAULT: 
> 
> ```sql
> ALTER TABLE customer
> ALTER COLUMN status DROP DEFAULT
> ``` 


---

PRIMARY и FOREIGN KEY также являются ограничениями!!!
